# PiForge v0.12.0 — 项目归用户管 · 数字与开关说真话

发布日期：2026-11-04

本次把 v0.11.3、v0.11.4 两次未公开发布的版本一并带上线（上一个公开版本是 v0.11.2），
再加上新的开发护栏与完整的 README / 发布说明重写。

## 亮点

### 项目归你自己管

左栏项目行悬停 `⋯` 或右键 → 「重命名项目」/「从侧栏移除」。

- 只改左栏显示名与可见性，磁盘目录与会话归属都不动；
- 只写一条本地偏好（`pi-sidebar-projects-v1`），不删会话、不碰目录；
- 以后用「新建项目」选回同一目录即自动恢复显示；改成空或改回文件夹原名 = 恢复默认。

### 用量先说真话

- 费用只报真实 `usage` 累计，去掉流式阶段的估算叠加：没收到 `usage` 就不显示数字。
- 实时用量按会话隔离，别的会话在跑不再累加到当前这条用量条。
- 千以上缩写：< 1000 精确整数，≥ 1000 一位小数（`2.9K` / `69.8K`），≥ 999,950 进位 `1.0M`。
- 流式事件按帧合并、工具卡秒表 tick 局部化、打字 / 切会话 / 切面板的重渲染剪枝。

### 注入开关先说默认

- **AGENTS.md / CLAUDE.md 注入**：可按「跟随全局 / 开 / 关」三态控制，全局 + 项目级都可设，默认开。
- **HANDOFF.md 接续注入**：项目根或 `docs/` 下的 HANDOFF.md 可注入系统提示词，默认关。
- **压缩摘要**：固定中文、更简洁，默认只接管摘要正文。

### 看门狗看得懂长活

- 停滞阈值默认 20s → **90s**，且 90s 就是最低档（运行期传更小的值会被钳住），上限仍 10min。
- 下拉预设改为 90 / 120 / 300 / 600 秒；扫描周期仍 5s、连续 2 次超阈值升级，即默认约 100s
  无有效进展才亮红灯。
- 依然**零 Token、零 prompt 注入**：只在程序层看有没有有效进展。

### Pi 核心 1.5.0

- 三个 `@earendil-works/pi-*` 包精确锁定到 `1.5.0`（传递依赖新增 `pi-schema`）。
- 上游工具参数校验改由 `pi-schema` 执行；PiForge 的工具全是普通 JSON Schema，
  唯一适配是 MCP `clientRegistration` 类型放宽到 `"auto" | "dcr" | "cimd"`。

### 开发体验

- `dev:electron` 新增前置护栏：`out/` 比源码旧时直接报错并提示 `npm run build:static`，
  不再让你对着旧 UI 调半天。`PIFORGE_SKIP_STATIC_FRESHNESS=1` 可降级为警告。
- 调用预算从「次数」改成「批次」：简单 1 批 / 普通 2–3 批 / 调研 3–4 批，单批并行 ≤ 12；
  到顶先交付可验证结论，剩余待办留给下一轮。

| 看门狗停滞阈值 | 默认 20s，最低 5s | 默认 90s，最低 90s（预设 90/120/300/600s） |

## 安装与兼容

- 安装包由 CI 构建：Windows NSIS（含 ZIP）、macOS Universal DMG + ZIP、Linux `.deb`，
  并对每个平台执行打包后的启动冒烟。
- **Windows 安装包未代码签名**，可能出现 SmartScreen 提示。
- **macOS 安装包未签名、未公证**，首次打开可能出现 Gatekeeper 提示。
- **Linux `.deb` 未做 debsig**：自动更新通过 `dpkg -i` / `apt --allow-unauthenticated` 安装，
  需要 root 授权；下载完整性由 `latest-linux.yml` 的 SHA512 校验，漏传该文件则收不到自动更新。
- 自动更新走 electron-updater 既有链路（检查 → 确认 → 下载 → 重启安装），更新源在构建期固定。
- 与终端 CLI 同时运行仍共享 `~/.pi/agent`；同一 session 两端同时写入仍不受支持。
