# PiForge v0.11.1

**English** · [简体中文](./v0.11.1.zh-CN.md)

Released: per the CI output of tag `v0.11.1` (Windows NSIS + ZIP, Linux deb, macOS universal).

This release is **bug fixes on top of 0.11.0 plus one new switch**; the call budget and tool defaults are untouched: pasted images no longer block the main thread, the tool-card stopwatch no longer keeps ticking, a broken event stream says so plainly, and a "project isolation" switch arrives, off by default.

> **Version note**: the `v0.11.0` tag sits on the `release/v0.11.0` branch, and `main`'s `package.json` is still at 0.10.0. This release merges `v0.11.0` back (the call budget, tool overhead compression and codemode changes are all in), then adds the four 0.11.1 changes — upgrading from 0.11.0 gets you the same content plus the items below, and you **will not fall back to 0.10.0**.

## Pasted images no longer block the input

Pasting a screenshot into the input visibly stalled, because three pieces of work all ran on the main thread:

- Scaling: a 4K original used to be `drawImage`d into a 1568px canvas (tens to a hundred-plus milliseconds, synchronously). It now uses `createImageBitmap(file, { resizeWidth, resizeHeight, resizeQuality: "high" })`, so decoding and resampling run on a worker thread and the main thread only moves an already-scaled small image (`lib/image-attachment.ts`).
- Encoding: clipboard screenshots are all `image/png` and their names do not contain "screenshot", so they were always re-encoded as PNG (encoding a 1.5MP PNG costs another one or two hundred milliseconds). A 24×24 sample now probes alpha, and **only genuinely transparent images stay PNG**; the rest become JPEG(0.92), while GIF/SVG are sent as-is.
- Preview: the 56px thumbnail in the paste strip used to mount the original image's object URL directly (decoding the whole 4K). A 160px thumbnail (`previewUrl`) is now generated as well, the large-image viewer uses a downsampled full image (`fullUrl`), and the `ImageBitmap` is explicitly `close()`d.

On the interaction side: after pasting, **a "processing" placeholder appears synchronously**; multiple images are processed serially with one frame yielded per image; `canSend` is false while processing, so Enter cannot silently drop an image that has not been converted yet; both object URLs are `revoke`d on remove / send / unmount.

## The tool-card stopwatch follows `tool_execution_end`

A tool card's duration freezes on completion instead of counting along with "the latest call" (`lib/tool-clock.ts` + `components/Transcript.tsx`). The same leftover timing pattern in `DevEnvironmentConfig` is fixed too.

## A broken event stream no longer pretends to be thinking

The old failure mode: the connection dropped, the UI sat at "PiForge is thinking…", and without clicking stop the user never saw the output already produced. New `hooks/agent-session/stream-health.ts` (pure functions, unit-testable) distinguishes three failures:

- `reconnecting`: the connection keeps failing, retryable;
- `failed`: reconnect attempts exhausted;
- `stalled`: connected but no real increment for 30 s (server buffering / subscription not attached).

The UI reports it through `components/StreamHealthBanner.tsx` instead of leaving the user guessing.

## New switch: project isolation (off by default)

Regular settings → runtime → "project isolation". With it on, a project can only read and write files **inside its own directory**, and everything else is `AccessDenied`; with it off, behavior is exactly as before (all session cwds are allowed).

- The policy still lives in the host: `authorizePath(target, op, scope?)` in `agent-host/allowed-roots.ts` gains one more check — when isolation is on, the path must fall inside "the current project" (`scope` first, then the activeScope reported by Next); **without a current project it fails closed** rather than degrading to "readable everywhere".
- Where the current project comes from: `Workbench` POSTs `/api/files/scope` when the active session's cwd changes → host `files.setScope` (already declared in `contract/methods.ts`). `file-index` / `git` / `statusline` / `processes` each pass cwd as their scope.
- The switch has a 2 s cache, so a change takes effect within seconds.
- Known boundary: with it on, worktree/scratch directories (outside the project) and paths like `~/.pi/**` are rejected; turn it off first when you need worktree collaboration.

## Artifacts

NSIS + ZIP + `latest.yml` (with SHA-256), the Linux deb and the macOS universal dmg/zip are built by `desktop-packages.yml` in CI after the `v0.11.1` tag is pushed; nothing is built locally.

The Windows installer is **not code-signed** and SmartScreen will warn about an "unknown publisher"; the macOS build is unsigned and not notarized, so the first launch needs right-click → Open (or `xattr -dr com.apple.quarantine`); the Linux deb has no debsig, so installation needs root authorization and integrity is verified by the SHA512 in `latest-linux.yml`.

## Migration and upgrade

- Upgrading from 0.11.0 / 0.10.0 needs no migration: sessions and settings live in `~/.pi` and `%APPDATA%\piforge` respectively.
- The new switch is off by default; file access scope only changes if you turn "project isolation" on yourself.
