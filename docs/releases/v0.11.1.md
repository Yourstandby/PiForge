# PiForge v0.11.1

发布日期：以 tag `v0.11.1` 的 CI 产出为准（Windows NSIS + ZIP，Linux deb，macOS universal）。

本版是 **0.11.0 之上的修 bug + 一个新开关**，没有改调用预算与工具默认值：贴图不再卡主线程、
工具卡秒表不再一直跳、事件流断了会明说，另加一个默认关闭的「项目隔离」。

> **版本口径**：`v0.11.0` 的 tag 打在 `release/v0.11.0` 分支上，`main` 的 `package.json`
> 还停在 0.10.0。本版把 `v0.11.0` 合并回来（调用预算、工具开销压缩、codemode 变更全都在），
> 再做 0.11.1 的四处改动 —— 从 0.11.0 升级你会拿到同样内容再加下面这些，**不会退回 0.10.0**。

## 贴图不再卡住输入框

截图贴进输入框时明显停顿，来源是三处都在主线程干的活：

- 缩放：以前把 4K 原图 `drawImage` 进 1568px canvas（几十到上百毫秒同步）。现在用
  `createImageBitmap(file, { resizeWidth, resizeHeight, resizeQuality: "high" })`，解码 + 重采样跑在
  工作线程，主线程只搬一张已经缩好的小图（`lib/image-attachment.ts`）。
- 编码：剪贴板截图都是 `image/png`、名字也不含 screenshot，以前一律重编码 PNG（1.5MP PNG 编码又要
  一两百毫秒）。现在 24×24 抽样探测 alpha，**只有真透明才走 PNG**，其余 JPEG(0.92)；GIF/SVG 原样发送。
- 预览：贴图条的 56px 缩略图以前直接挂原图 object URL（要解码整张 4K）。现在额外生成 160px 缩略图
  （`previewUrl`），大图查看器改用降采样整图的 `fullUrl`；`ImageBitmap` 显式 `close()`。

交互侧：粘贴后**先同步出现「处理中」占位**，多图串行处理、每张让出一帧；处理中 `canSend` 为 false，
避免 Enter 把还没转换完的图默默丢掉；移除/发送/卸载时两个 object URL 一并 `revoke`。

## 工具卡秒表以 `tool_execution_end` 为准

工具卡耗时完成即冻结，不再跟着「最新一次调用」继续数（`lib/tool-clock.ts` + `components/Transcript.tsx`）。
同时修掉 `DevEnvironmentConfig` 里同一模式的计时残留。

## 事件流断了不再假装在思考

以前的失败形态是：连接断了，界面停在「PiForge 正在思考…」，用户不点停止就看不到已经产出的内容。
新增 `hooks/agent-session/stream-health.ts`（纯函数，可单测）区分三种故障：

- `reconnecting`：连接反复失败，可重试；
- `failed`：重连耗尽；
- `stalled`：连上了但 30 s 没有任何真实增量（服务端缓冲 / 订阅没接上）。

界面用 `components/StreamHealthBanner.tsx` 明确告知，而不是让用户猜。

## 新开关：项目隔离（默认关）

常规设置 → 运行 →「项目隔离」。开启后一个项目只能读写**自己目录内**的文件，别的项目一律
`AccessDenied`；关着的时候行为与以前完全一致（所有会话 cwd 都放行）。

- 策略仍在 Host：`agent-host/allowed-roots.ts` 的 `authorizePath(target, op, scope?)` 多一道检查，
  隔离开启时路径必须落在「当前项目」（`scope` 优先，其次 Next 上报的 activeScope）内；
  **拿不到当前项目就 fail-closed**，不会退化成「全世界可读」。
- 当前项目来源：`Workbench` 在活动会话 cwd 变化时 POST `/api/files/scope` → Host `files.setScope`
  （`contract/methods.ts` 已声明）。`file-index` / `git` / `statusline` / `processes` 各自把 cwd 当 scope 传。
- 开关有 2 s 缓存，改完几秒内生效。
- 已知边界：开启后 worktree/scratch 目录（在项目外）与 `~/.pi/**` 这类路径会被拒，
  需要跑 worktree 协作时先关掉。

## 产物

NSIS + ZIP + `latest.yml`（含 SHA-256）、Linux deb、macOS universal dmg/zip 由
`desktop-packages.yml` 在 push `v0.11.1` tag 后于 CI 构建，本地不重复构建。

Windows 安装包**未代码签名**，SmartScreen 会提示「未知发布者」；macOS 包未签名未公证，首次打开需
右键 → 打开（或 `xattr -dr com.apple.quarantine`）；Linux deb 未做 debsig，安装时需 root 授权，
完整性由 `latest-linux.yml` 的 SHA512 校验。

## 迁移与升级

- 从 0.11.0 / 0.10.0 升级都无需迁移：会话与设置分别在 `~/.pi` 与 `%APPDATA%\piforge`。
- 新开关默认关；只有主动打开「项目隔离」才会改变文件访问范围。
