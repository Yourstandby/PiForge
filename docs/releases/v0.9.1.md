# PiForge v0.9.1

**English** · [简体中文](./v0.9.1.zh-CN.md)

Released: per the build output of tag `v0.9.1` (Windows NSIS + ZIP, Linux deb, macOS universal).

## Theme of this release: sub-agents are no longer declared dead after two turns

The v0.9.0 runtime audit (`docs/optimizations/subagent-runtime-audit.md`) measured one thing across 17 real dispatches: the sub-agent's **turn valve had an off-by-one** (`used < maxTurns` plus a default limit of 3), so it aborted at turn 3 — 8/8 cohesive module tasks were cancelled as "over turns" and conclusions already read were thrown away, leaving the main agent with a single `was cancelled`. The audit's success rate was 4/17 ≈ 24%.

v0.9.1 changes only the **valve, the settlement order and the failure response**; the parallel architecture and the prompt contract stay as they are:

- The default turn limit goes **3 → 6**, overridable with `PIFORGE_SUBAGENT_MAX_TURNS` (an invalid value falls back to the default with the reason stated).
- The predicate is fixed to `used <= maxTurns`: turn `maxTurns` is allowed, and only turn `maxTurns+1` is blocked.
- Settlement order becomes **idling → context → turns**: the limit (6) is deliberately higher than the idling threshold (5), which is the only way progress-guard gets a chance to act (under the old order it never did).
- The `ok:false` response is no longer a platitude: `status: need_help` + `turns N/limit` + `last_action` + `reason` + `next_steps` (re-dispatch / split into smaller tasks / switch to the persistent fleet), so the main agent can tell "missing context" from "a real infinite loop".
- The persistent fleet (herdr) passes `maxTurns = null`: no hard limit, sharing the same valve code with one-shot sub-agents.

Pi core also moves from 1.1.0 to 1.4.0 (with interface adaptation confined to `agent-host/sdk-adapter.ts` and the tests), and a weekly auto-upgrade radar is wired in.

## Added

- **Sub-agent output contract** (`agent-host/subagent-prompt.ts`, single source of truth):
  - Code changes must supply a `git diff` body in the `patch` field that `git apply` accepts; prose delivery is forbidden. Cannot produce a patch → `status: "need_help"` stating what is missing.
  - JSON constrains the **final reply only** (`status/conclusion/key_changes/patch/error_trace/next_steps`); the tool-calling stage is entirely free. This guards against a misreading observed in measurement (demanding structure and real work at the same time made the model skip tools and simply invent conclusions).
  - `PIFORGE_SUBAGENT_PROMPT=legacy|contract` rolls back, defaulting to `contract`; an invalid value falls back to contract with the reason stated.
  - `spawn_agent` and `herdr_*` share the same rules, differing only in their opening paragraph.
- **Sub-agent session isolation** (`agent-host/session-isolation.ts`): still `SessionManager.inMemory()` by default (nothing lands on disk), with new `PIFORGE_SESSION_DIR` for experiments / tools that need persistence.
- **Pi auto-upgrade radar** (`.github/workflows/pi-auto-upgrade.yml`): Mondays at 02:00 UTC plus manual dispatch; it reuses `npm run check:pi-updates` (now with `--json`) to decide whether it is behind → `npm i -D -E @latest` → build/tsc/lint/sdk-imports/the three affected unit tests → only when everything is green does it open a `chore/auto-upgrade-pi` PR. **PRs only, never releases**; installers and `latest*.yml` are still produced by `desktop-packages.yml`.

## Changed

- **Pi core `@earendil-works/pi-*` 1.1.0 → 1.4.0** (pinned exactly). Upstream 1.4.0 no longer includes `@earendil-works/chord`; `emitBeforeAgentStart` now receives a trigger object (`{ messageType, prompt }`) — that call only exists in tests, and production code never depended on it directly.
- `agent-host/sdk-adapter.ts` gains a `fauxToolCall` export: the anti-corruption layer remains the only file importing `@earendil-works/*` directly (`npm run check:sdk-imports` is green again).
- Now that the turn valve's limit is configurable, the `agent-guards.test.ts` assertion becomes "the limit must be higher than the progress-guard threshold (5)", so nobody can set the default back to 3 and silently disable the idling valve.

## Fixed

- The sub-agent turn valve's off-by-one: turn `maxTurns` was wrongly judged as over the limit, so only `maxTurns-1` turns ever produced anything.
- The `turns` count of `herdr` fleet agents was one turn short; it now matches one-shot sub-agents.
- A valve-triggered `need_help` body is no longer overwritten by `Cancelled` (they are two different failure paths).
- `agent-host/subagents.test.ts` used to import `@earendil-works/pi-ai` directly, bypassing the anti-corruption layer; it has been pulled back behind `sdk-adapter.ts`.

## Migration and upgrade

- **No mandatory migration**: the default prefix, declared tool set and cache lens are unchanged; the sub-agent contract already defaults to `contract`.
- To go back to the old behavior:
  - Old turn limit: `PIFORGE_SUBAGENT_MAX_TURNS=3` (6 when unset).
  - Old prompt: `PIFORGE_SUBAGENT_PROMPT=legacy`.
- **How to upgrade**: on Windows run `PiForge-Setup-0.9.1.exe` (an in-place install; sessions and settings stay in `~/.pi` and the app data directory); or extract the ZIP for a portable use. macOS / Linux: see the release assets.
- Client auto-update uses the existing electron-updater chain (`checkForUpdates` → `downloadUpdate` → `quitAndInstall`); the update source does not change in this release.

## Known issues

- **The context fuse (10k tok) is now the sub-agents' first bottleneck**: after loosening the turn valve, 8 more real dispatches saw tool call counts rise from 4–5 to 5–9 (no longer killed early), but the next wall is a single-turn context of 11.2k–18.2k tok tripping the fuse. This release **does not touch that threshold**; it is left as the starting point for the next optimization round.
- **The sub-agent success rate was not re-measured in this release**: the audit's 4/17 (≈24%) uses the old valve lens; this release only proves "no more early kills" and gives no new success-rate number. A new number requires re-running the three hypothesis experiments in `docs/optimizations/subagent-runtime-audit.md`.
- The audit scripts and probes under `tmp/subagent-audit/` are still not in version control (experimental assets, not part of the release package).
- Branches pushed by the auto-upgrade workflow with `GITHUB_TOKEN` do not trigger `ci.yml`; configure `AUTO_UPGRADE_TOKEN` (a PAT / App token) when you need CI to run on the PR, otherwise re-run it manually.

## Compatibility and known limitations

- The installers are not code-signed: SmartScreen may appear on Windows and Gatekeeper on macOS (unsigned and not notarized).
- The Linux `.deb` has no debsig, so installation needs root authorization; auto-update depends on `latest-linux.yml` in the release assets.
- The watchdog is still **observation and manual intervention**; it takes no automatic action.
- Running alongside the terminal CLI still shares `~/.pi/agent`; concurrent writes to the same session from both ends are still unsupported.
