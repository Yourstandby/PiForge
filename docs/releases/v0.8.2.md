# PiForge v0.8.2

**English** · [简体中文](./v0.8.2.zh-CN.md)

Released: per the build output of tag `v0.8.2` (Windows NSIS + ZIP, Linux deb, macOS universal).

## Theme of this release: make cost visible · make sub-agents actually work · make long sessions stop stalling

### 1. Context visualization: from "feels nearly full" to "you can see it"

- New `agent-host/context-budget.ts` (pure functions): converts usage into a ratio and level **relative to the hard cap** (observing 60% / critical 85% / over the cap), and the frontend only colors it.
- The conversation footer gains a 14px ring indicator: a full ring means at the hard cap, turning red means over the cap with a pulse; exact numbers go into the tooltip and `aria-label`, and the ring spins while compaction runs.
- The hard-cap constant still has exactly one source, `agent-host/compaction-plan.ts`; the display layer does not invent thresholds.

### 2. Sub-agents: grants, timeouts and idling settled in one pass

- New `agent-host/tool-grants.ts`: by default the parent agent's `activeTools` are **inherited**, and `bash / read / write / edit` are forcibly kept whenever they exist at runtime; when the parent explicitly passes `tools: [...]`, the union widens it; recursion and UI-side-effect tools (`spawn_agent`, `herdr_*`, `orchestrator_*`, managed processes, browser) are never granted downward; requesting a tool the runtime does not have throws `PERMISSION_MISSING` immediately, stated clearly in the first turn instead of idling until the fuse blows.
- Grants read the full registry from `pi.getAllTools()` and never a tool stub directory: enabling stubs does not affect escalation, and a sub-agent's tool set never writes back into the parent's declarations, keeping the prefix cache byte-stable.
- The fleet's per-turn timeout defaults to **5 minutes** (down from 15), overridable by the caller and clamped to 1s–30min; on expiry it `abort`s and terminates forcibly, leaving no zombie.
- **Auto-sleep after 5 minutes idle** (scanned every 60s): the `MAX_FLEET=4` slots are no longer eaten by hanging sessions; `herdr_spawn` supports "exit when done" one-shot tasks.

### 3. Output style: cut the fluff, not the reasoning

- New `agent-host/prompts/output-style.ts`: **pure static constants, no dynamic interpolation allowed** (the prompt cache matches by prefix, so a timestamp or path mixed in invalidates the whole segment). It demands deep thinking first, then forbids pleasantries and restating the question in the final output, requires diffs only when changing code, and forbids essays unless explicitly asked.
- `agent-host/desktop-output-style-extension.ts` merges it into the system prompt idempotently (skipped when already present).

### 4. Long sessions stop stalling: three workers + two caches + one cleanup

- `lib/jsonl-worker.ts`: session files >1MB go entirely into `worker_threads` (source inlined, so standalone needs no extra files); failures or timeouts fall back to inline parsing.
- `lib/git-status-worker.ts`: `git rev-parse` + `git status` move into a worker (20s timeout), and the main thread only converts cwd-relative paths.
- `lib/session-scan-worker.ts`: session index scanning and pagination likewise, so the first screen does not wait for a disk scan.
- `lib/transcript-turn-cache.ts`: turn objects are cached by "the message reference is identical **and** the tool result reference is identical", so streaming no longer re-renders everything every frame (fixing `turn 173 rendered 777 times`).
- `lib/chat-scroll-memory.ts`: when height cannot be measured under `display:none`, the last known scroll position is reused, so switching back to a tab no longer jumps to the first message.
- `lib/session-scope.ts` + `hooks/useSessionScope.ts`: every `setInterval` / `ResizeObserver` / `setTimeout` attached to a session (reconciliation, sticky-bottom scrolling, auto titling, optimistic refresh) is registered, and switching sessions or closing a tab calls `disposeSession()` once.

### 5. Session list pagination

- The first screen shows **20**, and scrolling to the bottom appends **10** at a time; the index TTL is 10s, scan concurrency 8, `SessionInfo` read concurrency 4, cache cap 400.
- Refreshing refetches to the loaded depth (`loadedDepthRef`), fixing the "project groups disappear and come back" jitter.
- Idle prefetching of the next batch (concurrency 1, 2s timeout); rows are marked "already open in a tab"; one list refresh is appended per finished turn (1.2s throttle).

### 6. Skills panel

- Skills carry `scope: global | project` and a source `agents | pi | package | other`, with project-level `.pi/skills` and user-level `~/.agents/skills` presented separately.
- Fixing the bug where under Git Bash / msys2 a `HOME=/c/Users/x` produced nonexistent Windows paths and dropped user-level skills wholesale (the real home directory is aligned during the call, with a serial lock).
- Automatic keyword classification (design / frontend / backend / testing / docs / release / workflow / meta-skill / other) plus a one-line summary; manual classification is stored in `localStorage` and never pollutes `SKILL.md`; scan results are cached for 5s.

### 7. Images

- Pasted images are first scaled locally to the vision model's **1568px** long-edge limit (`createImageBitmap` + `OffscreenCanvas` on the compositor thread): the model sees the same information while upload size and billed tokens drop 4–10×; if any step is unavailable it falls back to reading the original.
- The scaling note is shown to the model only and stripped before rendering, so users never see "words they never said".
- Clicking any image in the conversation or tool output opens a lightbox: zoom / pan / rotate / download / copy / page, with keyboard `+ - R`.

### 8. Receipts, ownership and the status bar

- **Turn-finished card**: only the "busy → idle" transition counts as finishing, and it carries a summary of the last reply (truncated at 1,200 characters); background tabs keep a green dot until switched back to.
- **Agent ownership**: the right panel groups by `project › session`, ordered `session > project > other`, with running entries pinned first; every bit of data flows over the existing SSE (`subagents` / `fleet`), zero polling.
- **Status bar makes room**: the engine health dot and pi core version move into a "system status" popover in the title bar (the upstream version is not queried unless the popover is opened); quota/balance becomes a fixed-width area on the right, so changing numbers no longer widen the whole row; amounts show 3 significant digits (`0.001034` is no longer degraded to `<0.0001`).

## Compatibility and known limitations

- The Windows x64 installer is not code-signed, so the first run may trigger a SmartScreen prompt.
- Sub-agent tool grants widen to the core write tools by default (`bash/read/write/edit`), moving the safety check from "read-only purism" to "the parent agent narrows explicitly"; orchestrator and UI-side-effect tools are still never granted downward.
- The 3 skipped tests are skipped by platform condition, not functional defects.
