# PiForge v0.9.3

**English** · [简体中文](./v0.9.3.zh-CN.md)

Released: per the CI output of tag `v0.9.3` (Windows NSIS + ZIP, Linux deb, macOS universal).

> This is the first official Release after 0.9.1, so it also contains what was planned as 0.9.2 (the agent-host single-file bundle taking cold start from 32 s to sub-second, the context budget copy, and dual-threshold lazy rendering in the message area); see [`v0.9.2.md`](./v0.9.2.md). Below only the nine changes added after 0.9.2 are described.

## Theme of this release: show what has already happened

Nothing architectural changed after 0.9.2; all nine changes circle the same idea — **what you see in the UI must match what actually happened in the system**:

- While the model thinks for a long time, the UI shows only one line "thinking…", and the content appears only after thinking ends;
- Reopening a long session that was compacted makes the questions from before the compaction disappear from the UI (on this machine one session with 77 questions showed only 7);
- In packaged builds, a received large image always becomes a `[Image omitted: could not be resized ...]` placeholder;
- Clicking a file while a conversation runs does not expand the right panel, or expanding it wedges the session;
- After a watchdog intervention, the model treats "which tool are you stuck on" as a new question and ends the turn once answered;
- A dark UI is missing — light theme all day, nothing to switch to at night.

## Added

- **Night mode** (`lib/theme.ts` + `components/ThemeBoot.tsx` + `app/globals.css`)
  Regular settings gain a three-way choice: follow system / light / dark. The preference is stored in `localStorage["pi-theme"]`, an inline script in `app/layout.tsx` applies `data-theme` once before React (no first-paint flash), and after mount it corrects and watches `prefers-color-scheme`. `globals.css` gains a `:root[data-theme="dark"]` token group (`--color-*` and the older `--bg/--text` series side by side), and hardcoded light literals in older components are caught by a mapping table generated by `scripts/gen-dark-remap.mjs`.
- **Thinking streams as it happens, and each thinking segment is followed by its tool calls** (`components/Transcript.tsx`, `components/transcript-process.ts`) `RoundProcess` moves from two parallel arrays (thinking array + tool array) to time-ordered `groups[]` (one thinking segment plus the 0..N tools after it). While thinking it auto-expands, auto-follows the bottom inside its container, and renders only the last 2,400 characters of the body; it collapses automatically once body output starts. A pure rendering change: nothing is sent back to the model, token cost 0.
- **Message timestamps**: questions / thinking / answers show `HH:MM` in the lower left (with `M/D` added across days); when older data has no `timestamp` the block is not rendered at all.
- **Merge-back commands for worktree workers**: `orchestrator_status` now includes `mergeBackHint` — two read-only commands (`log` / `diff --stat`) and one write operation (`merge --no-ff`), with quoting applied when a path contains spaces. It only offers commands, it never runs them; whether to squash and how to handle conflicts is left to you.

## Fixed

- **History from before compaction no longer disappears** (`lib/session-reader.ts`): `buildSessionContext` used to go through `buildSessionProjection()` (the projection shown to the model, which keeps only entries after the latest compaction); it now walks the `parentId` chain for the full set. Compaction is projected as a single custom marker (outside the question ticks), and the pre-compaction segment is slimmed down (long text / thinking truncated to a preview, images replaced by placeholders). Worst-case session payload 25 MB → 3 MB with the median unchanged; `entryIds` and `messages` still map one to one, so fork / rewind alignment is unchanged.
- **Packaged builds no longer swallow oversized images**: the bundle is ESM, and the inlined SDK `photon_rs.js` reads `photon_rs_bg.wasm` via `__dirname`, which is undefined in the bundle and whose wasm was not copied → `loadPhoton()` was always `null` → any image needing scaling/encoding returned a placeholder outright. The banner now provides `__dirname` and `runtimeAssets` copies `photon_rs_bg.wasm` next to the bundle. A 6000×3000 PNG: `ok:false` before, `ok:true` (2000×1000) after.
- **Clicking a file during a conversation no longer wedges it**: opening a file or diff always expands the right panel; large files (>80 KB of text) no longer go through Prism's synchronous highlighting (which saturates the main thread and freezes streaming replies and the input together) but degrade to plain line rendering, truncated to 4,000 lines; an agent's automatic reveal no longer steals the view you are reading.
- **The original task continues after a watchdog intervention**: `CONTINUE_AFTER_INTERVENTION` is extracted, and the `skip` / `ask` / `ask_brief` instructions all share "continue immediately once answered, do not end the turn, do not write a wrap-up"; stall detection goes from 10 s × 3 to 5 s × 2 (about 25 s to a red light), and a manual stop is allowed even while the task is still running.
- **A message whose `content` is a string no longer breaks the ErrorBoundary**: text extraction is unified in `lib/message-content.ts`, and three hand-written branches collapse into one call.

## Artifacts

This version produces only a **portable directory** locally (`npm run pack` → `release/win-unpacked/PiForge.exe`, double-click to run, no install information registered). Installers / deb / dmg are built by `desktop-packages.yml` in CI after the `v0.9.3` tag is pushed; nothing is built locally again, to avoid two divergent sets of artifacts.

## Migration and upgrade

- Upgrading from 0.9.2 needs no migration; sessions and settings live in `~/.pi` and `%APPDATA%\piforge` respectively.
- Night mode defaults to "follow system", so existing users still see the original light frost-blue on first start (when the system is light).
- For the portable build, simply replace the `win-unpacked` directory; for the installed build, install `PiForge-Setup-0.9.3.exe` from the release assets over the old one.
