## Improved

- **Extension models reach the selector**: `createPiRuntime` goes through the official `createAgentSessionServices`, exposing providers / models dynamically registered by local Pi extensions to `/api/models` and `/api/auth/*`. As the UI for the local Pi Agent, the desktop app's model list and authentication panel now line up with the terminal CLI (#34)

## Compatibility and known limitations

- The Windows / macOS / Linux installers are all unsigned. SmartScreen may appear on Windows, Gatekeeper on macOS, and Linux auto-update installs the unsigned `.deb` through `dpkg`/`apt`, which needs root authorization. A Release must carry all of `latest.yml` / `latest-mac.yml` / `latest-linux.yml`; omitting one means that platform receives no updates.
- Providers authenticated only through environment variables (such as GitHub Copilot) do not support saving an API key in the dialog.
- The model list loads extensions according to the process cwd; whether project-level extensions appear depends on the directory the app was started from. Extension load failures are currently silent, so the list may be missing entries.
