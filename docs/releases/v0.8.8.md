# Pi Agent Desktop v0.8.8

**English** · [简体中文](./v0.8.8.zh-CN.md)

Released: 2026-09-11

## Fixed

- **The crash fallback no longer leaves a permanent white screen**: the automatic reload after a renderer crash was capped at 3 times within a 60-second window; once the cap was reached it previously only logged and left the window blank. It now loads a startup error page saying "the page crashed several times, automatic recovery has stopped", so the user can see it and restart the app (#20)
- **Cross-process SQLite lock contention no longer means a 500 every time**: when running alongside the terminal CLI, LTM (long-term memory) `/api/memory/*` requests retry a bounded number of times under `SQLITE_BUSY` — fast failures (such as a `journal_mode=WAL` switch) retry to the full budget, while slow failures (a long transaction that burns out busy_timeout) retry at most once, so request latency does not multiply
- **Config writes are atomic**: `settings.json` and `desktop-settings.json` switch to tmp+rename atomic writes, with bounded retries when rename is blocked by concurrent readers with `EPERM` on Windows, and a fallback to a direct write with a log entry once the budget is exhausted. This prevents config files from being left half-written and losing content when the desktop app and the terminal CLI run concurrently

## Added

- **Layout-level error fallback**: new `global-error.tsx` (self-contained document and styles, context-free copy lookup), so a crash of the root layout itself also gets a retryable error page; frontend `unhandledrejection` / `window error` are caught globally with throttled notices and no new dependencies
- **Child process crashes are observable**: the main process listens for `child-process-gone` (GPU and others) and records type / reason / exit code

## Documentation

- `docs/investigations/white-screen.md`: the sandbox experiment record for the white-screen problem (reproduced in isolation with `PI_CODING_AGENT_DIR`), including the evidence-based verdict on three causal chains and the basis for the fixes

## Compatibility and known limitations

- The Windows / macOS / Linux installers are all unsigned. SmartScreen may appear on Windows, Gatekeeper on macOS, and Linux auto-update installs the unsigned `.deb` through `dpkg`/`apt`, which needs root authorization. A Release must carry all of `latest.yml` / `latest-mac.yml` / `latest-linux.yml`; omitting one means that platform receives no updates.
- Running alongside the terminal CLI still shares the `~/.pi/agent` directory; this release fixes two classes of conflict — config writes and LTM lock contention — and `.jsonl` session files proved robust in measurement, but concurrent writes to the same session from both ends are still unsupported.
- The final trigger mechanism of #33 ("desktop white screen while another terminal is running") still awaits user logs; this release eliminates the demonstrable damage chains within it.
