# PiForge v0.12.1 — 计划模式不再重发上下文

发布日期：2026-11-13

上一个公开版本是 v0.12.0。本次只有两条修复，都跟「计划模式」有关：一条是钱（前缀缓存不再被
plan 切换清空），一条是体验（输入框上方的进度卡片第一次真的会出现）。

## 亮点

### 切 plan 不再烧掉整段缓存

以前切到 / 切出 plan 模式，会同时改动两样东西 —— system prompt 里的计划段落、以及工具声明数组。
两者都在请求最前面，任何一字节变化都会让之后的整段历史作废，下一次请求按全价重发。
长会话里这一下就是几万到十几万 token，界面上会弹「前缀已失效，本次请求将重发 ≈N tok」。

现在：**工具声明只跟工具预设走，与模式无关**；计划段落改成尾部一条 display:false 的上下文消息。
plan 与执行模式的前缀字节完全一致，来回切换只多一条尾部消息。

### 计划进度卡片第一次真的会出现

输入框上方的步骤卡片此前在真实会话里**一次也不会渲染**：会话里记录的工具调用块是
{id, name, arguments}，而折叠进度的函数只认 {toolCallId, toolName, input} —— 字段名对不上，
永远折叠出空。现在两种形状都认。顺带修好「工具调用统计」里全部落进 unknown 的同一个毛病。

### plan 工具不再被存根

工具数量多时，扩展工具只保留名字不注入完整定义。plan 若被存根，模型拿不到参数说明就不会调用，
卡片也就永远空着。现在它和 tool_search、desktop_use_tool 一样恒常驻。

## 行为变化（请注意）

- **plan 模式下模型能看到 write / edit / MCP / 插件工具的 schema**，实际调用会被执行期拦下，
  返回理由为 `Plan mode: planning only`。
- 这是刻意的取舍：只要声明随模式变化，切换就必然重发上下文；用「看不见」换「不重发」，
  在长会话里省下的是真金白银。
- plan 的只读语义、批准流程、卡片位置与交互都没有变。

## 安装提示

三端安装包仍未签名，与 v0.12.0 相同：

- **Windows**：SmartScreen 会拦，选「更多信息 → 仍要运行」。
- **macOS**：Gatekeeper 会拦，右键 → 打开，或执行 xattr -dr com.apple.quarantine。
- **Linux**：.deb 未签名，需 sudo dpkg -i（AppImage 直接运行）。
