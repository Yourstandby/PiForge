# PiForge v0.12.1 — plan mode no longer resends context

**English** · [简体中文](./v0.12.1.zh-CN.md)

Released: 2026-11-13

The previous public version was v0.12.0. This release has only two fixes, both about plan mode: one about money (the prefix cache is no longer wiped by switching into plan) and one about experience (the progress card above the input actually appears for the first time).

## Highlights

### Switching into plan no longer burns the whole cache

Switching into or out of plan mode used to change two things at once — the plan section inside the system prompt and the tool declaration array. Both sit at the very front of the request, so any change of a single byte invalidates the entire history after it and the next request is resent at full price. In a long session that is tens to hundreds of thousands of tokens, and the UI pops up "prefix invalidated, this request will resend ≈N tok".

Now: **tool declarations follow the tool preset only, independent of mode**, and the plan section becomes a single trailing `display:false` context message. Plan and execute produce byte-identical prefixes, and switching back and forth only adds one message at the tail.

### The plan progress card appears for the first time

The step card above the input **never rendered even once** in a real session: the tool call blocks recorded in a session are `{id, name, arguments}`, while the function that folds progress only understood `{toolCallId, toolName, input}` — the field names did not match, so folding always produced nothing. Both shapes are accepted now. The same defect that pushed every entry of "tool call statistics" into `unknown` is fixed along with it.

### The plan tool is no longer stubbed

With many tools, extension tools keep only their name and do not inject the full definition. A stubbed plan tool leaves the model without parameter documentation, so it never calls it and the card stays empty forever. It is now always resident, like `tool_search` and `desktop_use_tool`.

## Behavior changes (please note)

- **In plan mode the model can see the schema of write / edit / MCP / plugin tools**, and the actual call is blocked at execution time with the reason `Plan mode: planning only`.
- This is a deliberate trade-off: as long as declarations vary with mode, switching necessarily resends context; trading "cannot see" for "does not resend" saves real money in long sessions.
- The read-only semantics of plan, the approval flow, the card's position and its interactions are all unchanged.

## Install notes

The three installers are still unsigned, as in v0.12.0:

- **Windows**: SmartScreen will block it; choose "More info → Run anyway".
- **macOS**: Gatekeeper will block it; right-click → Open, or run xattr -dr com.apple.quarantine.
- **Linux**: the .deb is unsigned and needs sudo dpkg -i (the AppImage runs directly).
