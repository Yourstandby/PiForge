# PiForge v0.9.0

**English** · [简体中文](./v0.9.0.zh-CN.md)

Released: per the build output of tag `v0.9.0` (Windows NSIS + ZIP, Linux deb, macOS universal).

## Theme of this release: stuck is visible, intervention is one click

v0.9.0 adds a **no-progress watchdog and human intervention**: monitoring lives entirely in the program layer (an in-memory state machine plus a timer), issues no LLM request at all, and writes not a single byte into the system prompt or the conversation history. When a task gets stuck, the "system monitor" panel on the right lights up and you can click **Skip (force skip)**, send a **minimal question** (tools forbidden, 20 characters max), or start a **deep diagnosis**. Every intervention goes through the existing steer / queue / prompt paths; there is no new direct model connection.

Alongside it: the usage strip sits permanently under the input; on narrow windows (≤1080px) the sidebar becomes an overlay; and copying from the image lightbox / showing large images is fixed.

This release also ships the v0.8.3 cost work for the first time (tools 23 → 12, on-demand tool domains, result deduplication, cache warming); v0.8.3 was never released separately.

## Added

- **No-progress watchdog**: on by default, 20s without meaningful progress counts as a suspected stall (three consecutive scans escalate to `stalled`, a single tool over the threshold escalates immediately), with backoff notices at 30s / 60s / 120s and then `failed` (UI only, no intervention on the model). Two rulers: `lastActivityAt` (a successful, non-duplicate action / body increment) and `lastLivenessAt` (signs of life); under concurrency each tool gets its own record keyed by `toolCallId`.
- **Human intervention (HITL)**: `Skip` / `minimal question` (default) / `deep diagnosis`; host-side guards: 3s cooldown per action, at most 5 per task, and an outright rejection when no task is active.
- **Right-side "system monitor" panel**: heartbeat, per-tool timing, suspected blockers, backoff notices, JSON details, and hot-switchable stall threshold (15/30/60/90 seconds, memory only); read-only status lights in three places — session list / tab bar / tool cards.
- **Usage strip**: tokens, cache hits, context occupancy and upstream quota sit permanently under the input; opening it is still the "usage and quota" dialog.
- **Overlay sidebar on narrow viewports**: at ≤ 1080px the left and right columns become overlays collapsed by default, and the chat area gets the full width.

## Changed

- Upstream quota is requested once (the input's usage strip fetches it and the bottom bar reuses the same snapshot).
- The thinking tier menu goes 3 → 4 (`auto` / `high` / `medium` / `low`), no longer filtered by model capability; unsupported tiers are converged by the backend, and values persisted by older sessions still display normally.
- Session status light priority: watchdog red (stalled) > running blue > waiting for action amber > background done green.

## Fixed

- The image lightbox's "copy" always failed before: `clipboard.write` only accepts `image/png`, so the image is now redrawn as PNG first.
- The lightbox shows the original image (`previewUrl`) first, instead of using the downsampled image sent to the model (long edge 1568) as the large view.
- In the lightbox's context menu, `Esc` closes the menu first; the toolbar makes room under the Electron window drag strip.

## Migration and upgrade

- **No mandatory migration**; the default prefix, tool declarations and hit rate are unchanged.
- To go back to v0.8.2 behavior exactly: `PIFORGE_WATCHDOG=0` (no timer, no state recorded, `watchdog.status` returns only `{enabled:false}`) plus `PIFORGE_ON_DEMAND_DOMAINS=0` (all tools resident, prefix 6,988).
- On-demand domain priority is unchanged: environment variable `PIFORGE_ON_DEMAND_DOMAINS` > setting `onDemandDomains` > default `shell`; `=1` is still the historical alias for `memory` + `orchestrator` on demand, not "all on demand".
- **How to upgrade**: on Windows run `PiForge-Setup-0.9.0.exe` (an in-place install; sessions and settings stay in `~/.pi` and the app data directory); or extract the ZIP for a portable use. macOS / Linux: see the release assets.
- **Not in this release**: the uncommitted auto-update work in the workspace (`electron/app-update*`, `useAppUpdater`, `AppUpdateRow`) and frame coalescing (`hooks/agent-session/frame-coalescer.ts`) are still WIP and did not enter v0.9.0.

## Known issues

- `npm test` has **2 failures**, both in **untracked WIP test files**, unrelated to v0.9.0:
  - `electron/auto-update-controller.test.ts`: the import is missing the `.ts` suffix (`ERR_MODULE_NOT_FOUND`);
  - `lib/agent-host-client.test.ts`: waits for a host handshake retry that is not implemented yet.
- Both failed **before any work on this release began** (same code, same result); they are not introduced here. Fixing them requires changing WIP code, which this release forbids, so they are left as-is and disclosed here.

## Compatibility and known limitations

- The installers are not code-signed: SmartScreen may appear on Windows and Gatekeeper on macOS.
- The watchdog is **observation and manual intervention**; it takes no automatic action. Automatic skip / automatic process kill remain on the roadmap (see the README).
- Intervention instructions enter the conversation history (they are your own instructions); automatic watchdog notifications do not (they stay in the UI queue only).
- Running alongside the terminal CLI still shares `~/.pi/agent`; concurrent writes to the same session from both ends are still unsupported.
