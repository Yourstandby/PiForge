# PiForge v0.12.3 — 不再卡在「等待首个 token」，发出去就有反应

发布日期：2026-11-25

上一个公开版本是 v0.12.2。本版没有新开关：一条反复复发的事件流卡死被拔掉根，
消息不再静默丢弃，Pi 核心跟到 1.6.0。

## 亮点

### 卡在「等待首个 token」——刷新才看得见，现在 12 秒自愈

现象：发了消息，界面停在「PiForge 正在思考… / 等待首个 token…」一动不动；手动刷新一下，
刚才那段回答整整齐齐全在。反复发生，只能靠刷新。

根因是**投递水位错位**。宿主的 `lastDeliveredSeq` 是「投给任意一个订阅就算送达」，
而 Next 侧的订阅 hub 会在浏览器取消 SSE 的瞬间被摘掉 —— 但那一刻已经发出 `agent.subscribe`，
于是在宿主上留下一个**没人消费的孤儿订阅**：它继续吃掉每一帧事件，水位一路涨到浏览器从没收到
的位置。下一次续发就从水位之后开始，那一段永久丢失，只有刷新（从磁盘重载 transcript）
才看得见。

修法三处：

- **不再产生孤儿订阅**：建订阅前后都校验 hub 是否还是当前那一个，发现已被摘掉立即
  `agent.unsubscribe`；`close()` 只删自己那一个，避免并发时误删新 hub。
- **续发按「真的交到监听者手里」算**：新增跨 hub 存活的 `agentListenerSeq`，
  没有显式 `fromSeq` 时用它续发，不再盲信宿主水位。
- **卡住自己恢复**：新增 12s「本轮一条真实事件都没收到」判定（真实增量时间戳，
  不含 `connect()` 的重连簿记），自动重连（带浏览器真实水位，宿主从 buffer 续发漏掉那段）
  + 从磁盘重载本轮已产出内容；15s 冷却、每轮最多 4 次。已经在流式 / 工具轮次里
  仍用 120s 长阈值，不打扰长工具。

### 发出去就有反应：不再静默丢弃

- 撞上「宿主还在跑」不再直接 `return`：改走排队（可见 /可编辑 / 立即可发），宿主真空闲时立刻开新一轮。
- 发送闸门会自己过期（8s）：一次丢事件不再把闸门永久卡死。
- 失败会留下来：气泡标「未送达」，输入框上方常驻原因 + 重试 / 忽略。
- 宿主重载资源期间不再拒收消息（并发重载改成复用同一个在途 promise）。

### Pi 核心升到 1.6.0

三包（`pi-ai` / `pi-coding-agent` / `pi-mcp`）精确锁定 1.6.0。PiForge 自身零代码改动
（只经 `sdk-adapter.ts` 一个接缝 import 上游）。

来自上游的行为变化，请注意：

- `openai` / `azure` / `openai-codex` 的默认模型换成 GPT-6.2 Sol（同价）。
- `find` 的 path pattern 改为相对搜索目录（`src/*.ts` 不再匹配 `pkg/src/a.ts`，跨层要写 `**/src/*.ts`）。
- GPT-6.2 两档模型不接受 reasoning effort `none` / `minimal`，即「思考等级 off」在这两个模型上不可用。

## 行为变化（请注意）

- 事件流卡住不再需要手动刷新或点停止：12s 内自动恢复（重连 + 从磁盘补内容）。
- 运行中按发送会进排队，被宿主拒收的气泡带「未送达」标记（v0.12.2 起的行为保持不变）。
- 默认模型、`find` 的匹配口径、思考等级上限按上游 1.6.0 变化，见上。

## 安装提示

三端安装包仍未签名，与 v0.12.2 相同：

- **Windows**：SmartScreen 会拦，选「更多信息 → 仍要运行」。
- **macOS**：Gatekeeper 会拦，右键 → 打开，或执行 `xattr -dr com.apple.quarantine`。
- **Linux**：`.deb` 未签名，需 `sudo dpkg -i`。
