# Pi Agent Desktop v0.8.9

**English** · [简体中文](./v0.8.9.zh-CN.md)

Released: 2026-09-23

## Added

- **Usage panel**: the top status bar shows the session's input / output tokens, cache reads and writes, and context occupancy; a dialog summarizes session usage, model information and context window capacity.
- **Upstream quota query**: shows the quota windows and reset countdowns for OpenAI Codex, DeepSeek, OpenRouter and Anthropic. Data is queried through provider credentials available on this machine; the quota endpoints use a short-lived cache and a rate limit on forced refreshes.

## Fixed

- **Error responses stay uniform**: failures in the agent event stream initialization and the long-term memory API return structured JSON errors with a request ID; when the SQLite busy lock exhausts its retries it returns an explicit `503 ltm_busy`.
- **Usage refresh race**: an earlier query no longer overwrites a newer result; provider matching and the display for expired / unavailable credentials are improved.

## Security

- Next.js and `eslint-config-next` are updated to 16.3.6, with the affected transitive dependencies refreshed, patching the upstream [Windows server-side RCE](https://github.com/vercel/next.js/security/advisories/GHSA-p293-qw3h-jr36), [AVIF image optimization RCE](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4) and [next/og RCE](https://github.com/vercel/next.js/security/advisories/GHSA-vcvr-r3jv-pc5j); `npm audit` currently reports 0 vulnerabilities.

## Compatibility and known limitations

- Upstream quota depends on local credentials for supported providers and on the availability of the provider endpoints; without credentials or when a quota endpoint is unavailable, quota data is not shown as a valid result.
- The Windows / macOS / Linux installers are all unsigned. SmartScreen may appear on Windows, Gatekeeper on macOS, and Linux auto-update installs the unsigned `.deb` through `dpkg` / `apt`, which needs root authorization.
- Running alongside the terminal CLI still shares the `~/.pi/agent` directory; concurrent writes to the same session from both ends are still unsupported.
