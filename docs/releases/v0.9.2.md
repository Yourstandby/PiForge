# PiForge v0.9.2

**English** · [简体中文](./v0.9.2.zh-CN.md)

Released: per the build output of tag `v0.9.2` (Windows NSIS + ZIP, Linux deb, macOS universal).

## Theme of this release: agent-host cold start 32s → sub-second

The cold-start measurement in 0.9.1 put all 31.9 s **inside the agent-host child process, before it printed its first log line** (spawn → `heap flags`). Splitting it into a phase table showed:

- **≈90%** is per-file ESM module graph resolution — a 32-byte entry point that actually loads a module graph of 5,917 files / 143 MB in `standalone/node_modules`, measured at 3.1–3.5 s (longer on a cold cache).
- **≈10%** is Electron `utilityProcess` bootstrapping (spawn → first line ≈0.8 s).
- Defender's first scan right after installation is an **amplifier, not the cause**: cold/warm rounds went `4550 → 2670` and `1550 → 1064`, the ratio unchanged.

This release does exactly two things: bundle the host into a single file to erase the module graph, and make the context hard cap follow the window.

## Key numbers

| Goal | Before | After (3 cold starts) | Threshold |
| --- | --- | --- | --- |
| **G1** host ready (from app ready) | 2670 / 2796 ms | 1194 / 1064 / 867 ms → p50 **1064**, p95 **1194** | p50 ≤3000, p95 ≤5000 |
| **G2** fresh install first start | — | new copy directory + fresh userData = **1799 ms** (spawn→ready 1626 ms) | ≤8000 |
| **G3** UI interactive | p50 982 / p95 1013 | p50 **785** / p95 1076 | ≤1500 and no regression |
| **G4** `connect failed` / soft timeout | 7 / 1 | **0 / 0** | 0 |
| **G5** no functional regression | — | all 16 tools called manually and passed | all pass |

Lens: the win-unpacked artifact with an isolated `userData`, at least 30 s between runs, `bench/startup_stats.py` parsing `main.log`.

> **G2 is proxy acceptance**: a real NSIS install plus Defender's first scan was not run this round — the measurement session itself runs inside a PiForge process, and uninstalling / reinstalling would kill it. What is needed is repeating "uninstall → install → start immediately" on the 0.9.2 installer.

## Added

- **Single-file agent-host bundle** (`scripts/bundle-agent-host.mjs`): esbuild produces `agent-host/bundle/host.mjs` and the build verifies no bare imports remain. During packaging, `ensure-standalone-agent-host.mjs` copies it and generates a wrapper; **a missing bundle falls back to the per-file tree automatically**, so functionality is never tied to the bundle.
- **Phase timings** (`agent-host/host-phases.ts`): zero dependencies, emitting `[agent-host] [phase] <name> ms=<absolute> delta=<net>`, covering `node.bootstrap / server.module / config.sync / pipe.listen / ws.bus / plugins.init / ready`. `index.ts` now imports `server.ts` dynamically, otherwise every timing would land after the module graph load.
- **Startup statistics script** (`bench/startup_stats.py`, `bench/run-cold-starts.ps1`): one command prints "app ready → host ready, spawn → first line, app ready → static loaded" for each start, plus the phase table.

## Changed

- **Context compaction defaults back to pi**: PiForge's own desktop compaction extension (`desktopCompactionInlineExtension`) is no longer registered. Triggering goes through pi's `shouldCompact` + `DEFAULT_COMPACTION_SETTINGS` (`reserveTokens 16384` / `keepRecentTokens 20000`), and the summary is generated by pi too, no longer preempted and rewritten into four parts by `session_before_compact`. The self-built "window / budget / hard cap" strategy and its unit tests are kept, registered only under `PIFORGE_DESKTOP_COMPACTION=1`.
- The context budget copy changes from "x% used" to `used / window tokens` (`agent-host/context-budget.ts` + `components/UsageStrip.tsx` + `components/ChatSurface.tsx`); the denominator is the model's real window with no compaction cap mixed in — whether compaction happens and how much the window holds are two different things.
- Lazy rendering in the message area moves to **dual-threshold hysteresis**: hydrate at 1200px, unmount at 2000px (a single threshold oscillates: hydrate → grow past the boundary → unmount → shrink back). Scrolling up locks the sticky-bottom takeover, released only when the real distance from the bottom is < 40px.
- The restore-cost hint only shows when "just opened and nothing sent yet" and collapses once a run starts.

## Two SDK runtime couplings that must be handled

If only `host.mjs` is copied after packaging, functionality **breaks silently**; the build script carries one patch for each:

1. The Pi SDK's `dist/utils/image-resize.js` locates its Worker with `new URL("./image-resize-worker.js", import.meta.url)` → the build script copies that file next to `host.mjs`.
2. `getPackageDir()` walks up from `import.meta.url` looking for `package.json` (themes / quickjs wasm / export templates all rely on it) → the generated wrapper sets `PI_PACKAGE_DIR` **before** importing the bundle.
3. One more: `__require` in esbuild's ESM output needs `require` in scope, otherwise a CJS dependency (`cross-spawn → require("child_process")`) throws `Dynamic require ... is not supported` outright; the bundle banner adds `createRequire(import.meta.url)`.

## Known issues and follow-ups

- `ws.bus` (the WebSocket plugin bus listener) went from 64–88 ms to 19–59 ms and is still on the ready critical path; not optimized.
- `config.sync` 4–6 ms, `pipe.listen` 1–2 ms, `plugins.init` 2–4 ms: small enough, left alone.
- V8 compile cache showed unstable gains in measurement (5.5 s → 4.5–5.8 s) and is even less necessary after bundling; not adopted.
- The bundle is an uncompressed single file (about 15 MB), so stack traces show bundle line numbers; for debugging look at `agent-host/dist` or temporarily delete the bundle to fall back.
- `standalone/node_modules` **is still kept**: Next standalone, user extensions (jiti) and `PI_PACKAGE_DIR` all still use it, and deleting it would drag the layout along — out of scope for this release.

## Migration and upgrade

- Windows: run `PiForge-Setup-0.9.2.exe` for an in-place install; sessions and settings live in `~/.pi` and `%APPDATA%\piforge` and are unaffected.
- Upgrading from 0.9.1 needs no migration; the first start rebuilds the bundle under `resources/standalone/agent-host/`.
