# PiForge v0.9.2

发布日期：以 tag `v0.9.2` 构建产出为准（Windows NSIS + ZIP，Linux deb，macOS universal）。

## 本版主题：agent-host 冷启动 32s → 秒级

0.9.1 的实测冷启动把 31.9 s 全部发生在 **agent-host 子进程内部、且在它输出第一行日志之前**
（spawn → `heap flags`）。阶段表拆分后的结论：

- **≈90%** 是逐文件 ESM 模块图解析——入口 32 字节，实际加载 `standalone/node_modules`
  里 5,917 个文件 / 143 MB 的模块图，实测 3.1–3.5 s（冷缓存下更长）。
- **≈10%** 是 Electron `utilityProcess` 进程引导（spawn → 第一行 ≈0.8 s）。
- 首装后的 Defender 首次扫描是**放大器不是主因**：冷/热两轮 `4550 → 2670`、`1550 → 1064`，
  比例不变。

本版只做两件事：把 host 打成单文件 bundle 消掉模块图，把上下文硬顶改成跟窗口联动。

## 关键数字

| 目标 | 改前 | 改后（3 次冷启动） | 阈值 |
| --- | --- | --- | --- |
| **G1** host ready（app ready 起算） | 2670 / 2796 ms | 1194 / 1064 / 867 ms → p50 **1064**、p95 **1194** | p50 ≤3000、p95 ≤5000 |
| **G2** 首装首启 | — | 新拷贝目录 + 全新 userData = **1799 ms**（spawn→ready 1626 ms） | ≤8000 |
| **G3** UI 可交互 | p50 982 / p95 1013 | p50 **785** / p95 1076 | ≤1500 且不回退 |
| **G4** `connect failed` / soft timeout | 7 次 / 1 次 | **0 / 0** | 0 |
| **G5** 功能无回退 | — | 16 项工具逐个人工调用通过 | 全通过 |

口径：win-unpacked 产物 + 隔离 `userData`，每次间隔 ≥30 s，`bench/startup_stats.py` 解析 `main.log`。

> **G2 为代理验收**：真实 NSIS 安装 + Defender 首次扫描未在本轮执行——测量会话本身运行在
> PiForge 进程内，卸载/重装会杀掉自身。需要在 0.9.2 安装包上重复「卸载 → 安装 → 立刻首启」。

## 新增

- **agent-host 单文件 bundle**（`scripts/bundle-agent-host.mjs`）：esbuild 打 `agent-host/bundle/host.mjs`，
  构建后校验没有残留 bare import。打包时由 `ensure-standalone-agent-host.mjs` 复制并生成 wrapper；
  **缺 bundle 自动回退逐文件树**，不会把功能绑死在 bundle 上。
- **阶段打点**（`agent-host/host-phases.ts`）：零依赖，输出
  `[agent-host] [phase] <name> ms=<绝对> delta=<净耗时>`，覆盖
  `node.bootstrap / server.module / config.sync / pipe.listen / ws.bus / plugins.init / ready`。
  `index.ts` 对 `server.ts` 改为动态 import，否则所有打点都会落在模块图加载之后。
- **启动统计脚本**（`bench/startup_stats.py`、`bench/run-cold-starts.ps1`）：
  一条命令出「每次启动的 app ready → host ready、spawn → 第一行、app ready → static loaded」与阶段表。

## 变更

- `MAX_CONTEXT_TOKENS` 48k → **120k 保险丝**（`agent-host/compaction-plan.ts`），正常触发仍靠
  `45% × 窗口`；新增 `resolveContextCeiling()` = `min(120k, 窗口 × 0.8)`，
  窗口未知/非法时退回 120k。动机：32k 小模型在旧常量下永远不触发，1M 声明窗口又能涨到
  12 万还不压。同时把 120k 从「与模型无关的硬顶」重新定义为「读数异常时的兜底」。
- 上下文预算文案从「用了 x%」改为 `已用 / 窗口 token`（`agent-host/context-budget.ts` +
  `components/UsageStrip.tsx` + `components/ChatSurface.tsx`），分母是模型真实窗口。
- 消息区懒渲染改**双阈值滞回**：水合 1200px、卸载 2000px（单阈值边界会
  「水合 → 撑高越界 → 卸载 → 缩回」来回抖）。上滚即锁住贴底接管，解除点只有真正距底 < 40px。
- 恢复费提示只在「刚打开、还没发过消息」时显示，开始跑即收起。

## 两个必须处理的 SDK 运行时耦合

打包后如果只搬 `host.mjs`，功能会**静默坏掉**，构建脚本里各有一处补丁：

1. Pi SDK 的 `dist/utils/image-resize.js` 用 `new URL("./image-resize-worker.js", import.meta.url)`
   定位 Worker → 构建脚本把该文件复制到 `host.mjs` 旁边。
2. `getPackageDir()` 从 `import.meta.url` 往上找 `package.json`（themes / quickjs wasm / export 模板
   都靠它）→ 生成的 wrapper 在 `import` bundle **之前**设置 `PI_PACKAGE_DIR`。
3. 附带一条：esbuild ESM 输出里的 `__require` 需要作用域有 `require`，否则 CJS 依赖
   （`cross-spawn → require("child_process")`）直接抛 `Dynamic require ... is not supported`；
   bundle banner 里补 `createRequire(import.meta.url)`。

## 已知问题与后续

- `ws.bus`（WebSocket 插件总线监听）改前 64–88 ms、改后 19–59 ms，仍在 ready 关键路径上，未优化。
- `config.sync` 4–6 ms、`pipe.listen` 1–2 ms、`plugins.init` 2–4 ms：已足够小，不动。
- V8 compile cache 实测收益不稳（5.5 s → 4.5–5.8 s），bundle 之后更无必要，未采用。
- bundle 是未压缩单文件（约 15 MB），栈里出现的是 bundle 行号；排障需看 `agent-host/dist`
  或临时删掉 bundle 回退。
- `standalone/node_modules` **仍然保留**：Next standalone、用户扩展（jiti）与 `PI_PACKAGE_DIR`
  都还在用它，删掉会连带改布局，不在本版范围。

## 迁移与升级

- Windows：直接运行 `PiForge-Setup-0.9.2.exe` 覆盖安装，会话/设置在 `~/.pi` 与
  `%APPDATA%\piforge`，不受影响。
- 从 0.9.1 升级无需迁移动作；首次启动会重建 `resources/standalone/agent-host/` 下的 bundle。
