# PiForge v0.11.0

发布日期：以 tag `v0.11.0` 的 CI 产出为准（Windows NSIS + ZIP，Linux deb，macOS universal）。

本版主题：**把「卡住」变成看得见的数字**。调用预算第一次写死（每用户轮 <8 次工具调用、第 4 次
中途自检），工具固定开销整体压缩（输出预算 4k→24k 字符、默认超时 120s→45s）；codemode 恢复逐条
声明工具并能在脚本执行期间看到进度；界面侧修掉「点了没反应 / 一上翻就被拽回 / 工具卡一直跳秒」；
度量与冒烟脚本不再静默挂死（这是本版工程量最大的一块）。

默认行为变了五处，见文末「默认行为变没变」。

## 调用预算：每用户轮 <8 次工具调用

- **提示词拆成两条**（`agent-host/prompts/output-style.ts` 的 `BATCHING_RULES`）：「调用预算（写死）」
  与「中途自检」。简单任务 ≤4 次、普通 ≤8 次、调研 ≤10 次；禁用 `du -sh` 与全量 `grep -r`；
  重型命令显式 `timeout 30`；大量输出先用 `head` / `uniq` 摘要。仍是静态常量，只进一次前缀。
- **执行侧兜底**（`agent-host/desktop-tool-guard-extension.ts`）：新增 `TURN_BUDGET`
  （`softLimit: 4` / `hardLimit: 8`）与 `createTurnBudgetTracker()`。第 4 次调用的结果尾部追加自检
  提醒，第 8 次起追加停止探测并要求先交付结论；`before_agent_start` 复位计数，codemode 的嵌套调用
  不重复计数；与原有的并行提醒合并追加，不互相覆盖。
- 目标很直白：把「一轮问十几遍」压回 PAD 水平，调用次数与墙钟时间都被这两条同时约束。

## 工具固定开销压缩

- **输出预算**（`agent-host/tool-output-budget.ts`）：默认 4000 → **24000 字符**（≈6000 tokens），
  400 行兜底；超限时只留前 9000 + 后 9000 字符，截断提示补一句「需要全部内容请一次取完」。`read`
  的 4000 / 3000 / 1000 档位**不**跟着默认值缩放（否则 read 会从 120 行变成 720 行）；已截断文本
  二次裁剪直接返回（幂等）。
- **超时默认值**（tool-guard）：普通 120 → **45 s**，重型 900 → **300 s**，上限 600 → 300 s。
- **调度器配额**（`agent-host/desktop-tool-scheduler-extension.ts`）：全局重型 4 → **6**，单会话重型
  2 → **4**；轻量档（全局 12 / 会话 6）不变。上一版 4/2 在「隔壁开一个打包」时排得太久。
- 以上默认值全部仍由 `PIFORGE_TOOL_OUTPUT_CHARS` / `PIFORGE_TOOL_TIMEOUT_*` / `PIFORGE_SCHED_*`
  覆盖，A/B 臂不受影响。

## codemode

- **池上限可配**（`agent-host/codemode-worker-pool.ts`）：设置页 > `PI_CODEMODE_MAX_WORKERS` > SDK
  默认 2，范围 1–8。Host 启动与设置变更各打一行生效日志；SDK 每条脚本重读 env，改完下一条立即生效。
- **默认模式 `only` → `on`**（`lib/desktop-settings.ts`）：工具恢复逐条声明给模型，脚本仍是首选路径；
  显式写过 `only` 的老用户不受影响。
- **脚本内进度回传**（`lib/codemode-progress.ts` + `agent-host/desktop-codemode-observer-extension.ts`）：
  SDK 的 `tool_execution_update.details.calls` 在渲染层是空 `content`，长脚本执行期间界面一片静止。
  现在折成一行（`bash ✓1.2s · read … · edit ✗0.3s`，>5 条截断成 `… +N`）走既有 liveOutput 通道；
  脚本超时/取消时由观察扩展**推断**并打一行 `worker still exiting, slot held (pool=N)`（文案写明
  inferred，不假装是实时队列探针）。
- `scripts/hotfix/hotfix-codemode.ps1` / `.sh`：打包版 codemode-worker 热修复脚本。

## 界面

- **工具卡耗时完成即冻结**（新增 `lib/tool-clock.ts`）：秒表起点存在模块级 `Map`（键为 `toolCallId`），
  组件重挂载或历史分页不再从头计时；有 result 就停脉冲点、停运行态边框、停 200 ms 秒表；完成值优先
  用 pi 记录的 `durationMs`，旧会话用自测起止差兜底；历史加载的卡片没有起点，不会凭空显示巨大耗时。
  4 个单测覆盖。
- **标签切换 / 侧栏会话点击改为同步提交**：`setActiveKey` 与 `commitTabs` 原来包在 `startTransition`
  里，流式输出期间持续产生的紧急更新会不断打断它，表现就是「点了没有任何反应」且无报错。
- **上翻不再被自动贴底拽回**：`wheel` / `pointerdown` 接管监听的 deps 原本是 `[]`，首屏 loading/空态
  时滚动容器还没挂载，early return 后再也不会重绑；取消平滑滚动改用 `scrollTo({behavior:'instant'})`，
  写同名 `scrollTop` 取消不掉 smooth 动画。
- **介入提示不再冒充用户提问**：统一加 `[系统提示]` 前缀（`contract/intervention-marker.ts`），
  `Transcript` 识别后渲染成灰色系统卡片、隐藏分支/派生、不进回合导航刻度。

## 会话侧栏

- **首屏为每个项目补一条最新会话**（`lib/session-reader.ts`）：近期会话按 mtime 全项目混排，首屏 20 条
  常常全属于同一个项目，其余项目分组于是完全不出现（看着像升级后历史项目被清空）。现在额外给每个会话
  目录补上它自己最新的一条（只读该条 header），并返回 `nextOffset` 游标；前端追加改用游标而非已渲染
  条数，补齐项不会把中间会话跳过。

## 度量 / 冒烟脚本：不再静默挂死

这一块是本版的主要工程量。上一版开始，`measure:*` / `smoke:*` 在特定环境下会**零输出挂死**，
表现为「bash 卡住」，排查成本极高；本版逐层拆掉了。

- **等帧有硬期限**（`scripts/measure-prefix.mjs`）：每次等响应帧默认 60 s 超时，不再无限静默等待。
- **host 一死立即失败**：`createClient(endpoint, hostChild)` 监听子进程 `exit` / `error` 与 socket
  `close` / `error`，挂起的 waiter 全部立即 reject；socket close 比 child exit 先到时，最多等
  `HOST_EXIT_GRACE_MS = 700 ms` 把**退出码**并进错误（总耗时仍 ≤2 s），「崩了」和「被关掉了」分得开。
- **stdin 护栏只写一处**（新增 `scripts/lib/host-spawn.mjs`）：`hostChildEnv()` 在合并调用方 env
  **之前**写死 `PIFORGE_HOST_STDIN_CONTROL=0`，`spawnNodeHost()` 统一 spawn node 版 host。12 个脚本
  改走工厂，删掉各自手写的 `...process.env` 与护栏（上一版逐脚本手写，两次事故：duplicate `env:`
  覆盖前半段，端点与 token 全丢，host 直接 EADDRINUSE）。
- **`smoke:prefix-budget` 每步可见**：每步打一行开始/结束（含耗时），超过
  `PIFORGE_SMOKE_STEP_TIMEOUT_MS`（默认 300 s）杀掉整棵进程树并以 124 退出；Windows 上
  `taskkill /F /T`，避免 measure-prefix 被杀而 host 子进程留存。
- 修 `codemode-worker-pool` 测试的环境依赖：`applyCodemodeWorkerPool` 不传 env 时按模块加载快照解析，
  在带 `PI_CODEMODE_MAX_WORKERS=2` 的 Host 子进程里必红，改为显式传 `env: {}`。

## 默认行为变没变

变了，五处：

1. **codemode 默认 `on`**（v0.9.4 默认 `only`）：工具逐条声明回模型。显式写过 `only` 的配置不受影响。
2. **不显式传 `timeout` 的 shell 调用会在 45 s（重型 300 s）被打断**，比上一版的 120 s / 900 s 更紧。
   常驻进程、全量打包请显式传 `timeout`。
3. **工具输出预算 4000 → 24000 字符**：截断变少，但单条结果更占上下文（`read` 档位不变）。
4. **每用户轮工具调用软上限 4 / 硬上限 8**：第 4 次起结果尾部带自检提醒，第 8 次起带「先交付结论」。
   这两条是结果尾部追加的文本，不拦截调用。
5. **调度器重型配额放宽**到全局 6 / 单会话 4（轻量档不变）。

## 开关怎么用

- 输出预算：`PIFORGE_TOOL_OUTPUT_CHARS`（500–200000，默认 24000）。
- 超时护栏：`PIFORGE_TOOL_GUARD=0` 整体关闭；阈值走 `PIFORGE_TOOL_TIMEOUT_SECONDS` /
  `PIFORGE_TOOL_TIMEOUT_HEAVY_SECONDS` / `PIFORGE_TOOL_TIMEOUT_MAX_SECONDS` / `PIFORGE_TOOL_MAX_PARALLEL`。
- 调度器：`PIFORGE_TOOL_SCHEDULER=0` 关闭；配额走 `PIFORGE_SCHED_GLOBAL_HEAVY` /
  `PIFORGE_SCHED_GLOBAL_LIGHT` / `PIFORGE_SCHED_SESSION_HEAVY` / `PIFORGE_SCHED_SESSION_LIGHT` /
  `PIFORGE_SCHED_MAX_WAIT_MS` / `PIFORGE_SCHED_QUEUE_HINT_MS` / `PIFORGE_SCHED_MAX_HOLD_MS`。
- codemode：设置页「扩展与 MCP → Codemode」切 `on` / `only`；worker 池上限在同一处设置（1–8），
  优先级 设置页 > `PI_CODEMODE_MAX_WORKERS` > 2。
- 调试日志：`PIFORGE_DEBUG_TOOL_GUARD=1`、`PIFORGE_DEBUG_TOOL_SCHEDULER=1`。
- 冒烟/度量脚本的超时：`PIFORGE_SMOKE_STEP_TIMEOUT_MS`（默认 300000）。

## 已知限制

- 调度器与工具预算只在 Host 侧生效；直接跑 pi CLI 不继承这些默认值。
- codemode 的 worker 槽位在脚本超时后要能等到 worker 真正退出才释放，我们只能**推断**并打日志，
  没有队列状态接口（不 patch `node_modules`）。
- 每用户轮的调用预算是提示词 + 结果尾部提醒，不是硬拦截：模型仍可能越过 8 次，只是会被明确要求收尾。
