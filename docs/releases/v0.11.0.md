# PiForge v0.11.0

**English** · [简体中文](./v0.11.0.zh-CN.md)

Released: per the CI output of tag `v0.11.0` (Windows NSIS + ZIP, Linux deb, macOS universal).

Theme of this release: **turning "stuck" into visible numbers**. The call budget is hard-coded for the first time (<8 tool calls per user turn, with a mid-run self-check at call 4), fixed tool overhead is compressed overall (output budget 4k → 24k characters, default timeout 120s → 45s); codemode goes back to declaring tools one by one and now shows progress while a script runs; the UI fixes "clicked and nothing happened / scrolling up yanks me back / the tool card keeps ticking"; and the measurement and smoke scripts no longer hang silently (the largest piece of work in this release).

Five default behaviors changed; see "did default behavior change" at the end.

## Call budget: <8 tool calls per user turn

- **The prompt splits into two items** (`BATCHING_RULES` in `agent-host/prompts/output-style.ts`): "call budget (hard-coded)" and "mid-run self-check". Simple tasks ≤4 calls, ordinary ≤8, research ≤10; `du -sh` and a full `grep -r` are banned; heavy commands pass `timeout 30` explicitly; large outputs are summarized with `head` / `uniq` first. Still a static constant, entering the prefix once.
- **Runtime backstop** (`agent-host/desktop-tool-guard-extension.ts`): new `TURN_BUDGET` (`softLimit: 4` / `hardLimit: 8`) and `createTurnBudgetTracker()`. A self-check reminder is appended to the result of call 4, and from call 8 on a stop-probing notice demanding conclusions first; `before_agent_start` resets the counter, nested codemode calls are not double-counted, and it merges with the existing parallel-call reminder instead of overwriting it.
- The goal is blunt: push "asking a dozen times in one turn" back down to PAD level, constraining both call count and wall-clock time.

## Fixed tool overhead compressed

- **Output budget** (`agent-host/tool-output-budget.ts`): default 4000 → **24000 characters** (≈6000 tokens), with a 400-line fallback; when over the limit only the first 9000 + last 9000 characters are kept, and the truncation notice adds "if you need all of it, fetch it in one go". The `read` tiers 4000 / 3000 / 1000 do **not** scale with the default (otherwise read would go from 120 to 720 lines); already-truncated text is returned as-is on a second trim (idempotent).
- **Timeout defaults** (tool-guard): ordinary 120 → **45 s**, heavy 900 → **300 s**, cap 600 → 300 s.
- **Scheduler quotas** (`agent-host/desktop-tool-scheduler-extension.ts`): global heavy 4 → **6**, per-session heavy 2 → **4**; the light tier (global 12 / session 6) is unchanged. Last release's 4/2 queued for too long when "a packaging run was open next door".
- All of the above can still be overridden by `PIFORGE_TOOL_OUTPUT_CHARS` / `PIFORGE_TOOL_TIMEOUT_*` / `PIFORGE_SCHED_*`; the A/B arms are unaffected.

## codemode

- **Pool cap configurable** (`agent-host/codemode-worker-pool.ts`): settings page > `PI_CODEMODE_MAX_WORKERS` > the SDK default of 2, range 1–8. The host logs one effective line at startup and one per settings change; the SDK re-reads the env for every script, so a change applies to the next one.
- **Default mode `only` → `on`** (`lib/desktop-settings.ts`): tools are declared to the model one by one again, while scripts remain the preferred path; existing users who explicitly set `only` are unaffected.
- **In-script progress reported back** (`lib/codemode-progress.ts` + `agent-host/desktop-codemode-observer-extension.ts`): the SDK's `tool_execution_update.details.calls` have empty `content` in the renderer, so a long script left the UI frozen. It is now folded into one line (`bash ✓1.2s · read … · edit ✗0.3s`, truncated to `… +N` beyond 5) over the existing liveOutput channel; when a script times out or is cancelled, the observer extension **infers** and logs one line `worker still exiting, slot held (pool=N)` (the text says "inferred" — it does not pretend to be a live queue probe).
- `scripts/hotfix/hotfix-codemode.ps1` / `.sh`: hotfix scripts for the packaged codemode-worker.

## Interface

- **A tool card's duration freezes on completion** (new `lib/tool-clock.ts`): the stopwatch origin lives in a module-level `Map` keyed by `toolCallId`, so remounting a component or paginating history no longer restarts the timer; a result stops the pulse, the running border and the 200 ms tick; the final value prefers pi's recorded `durationMs`, with the measured start/end difference as the fallback for older sessions; cards loaded from history have no origin and never show an absurd duration. Four unit tests cover it.
- **Tab switching / sidebar session clicks commit synchronously**: `setActiveKey` and `commitTabs` were wrapped in `startTransition`, and the urgent updates streaming produces kept interrupting it — which looked exactly like "clicked and nothing happened", with no error.
- **Scrolling up is no longer yanked back to the bottom**: the deps of the `wheel` / `pointerdown` takeover listeners were `[]`, so when the scroll container was not mounted yet during first-screen loading/empty state, the early return meant they were never rebound; cancelling smooth scrolling now uses `scrollTo({behavior:'instant'})`, since writing the same `scrollTop` does not cancel a smooth animation.
- **Intervention notices no longer masquerade as user messages**: a `[system prompt]` prefix is applied uniformly (`contract/intervention-marker.ts`), and `Transcript` renders the recognized ones as gray system cards, hiding branch/fork actions and keeping them out of turn-navigation ticks.

## Session sidebar

- **The first screen adds each project's newest session** (`lib/session-reader.ts`): recent sessions are mixed across all projects by mtime, so the first 20 often all belonged to one project and the other project groups never appeared at all (it looked like historical projects were wiped after the upgrade). Each session directory now also contributes its own newest entry (reading only that entry's header) and a `nextOffset` cursor is returned; the frontend appends by cursor instead of by rendered count, so the added entries do not skip sessions in between.

## Measurement / smoke scripts: no more silent hangs

This was the bulk of the work in this release. Since the previous version, `measure:*` / `smoke:*` could **hang with zero output** in certain environments, showing up as "bash is stuck" and costing enormous debugging time; this release removes that layer by layer.

- **A hard deadline when waiting for frames** (`scripts/measure-prefix.mjs`): 60 s per response frame by default, no more infinite silent waiting.
- **Fail immediately when the host dies**: `createClient(endpoint, hostChild)` watches the child's `exit` / `error` and the socket's `close` / `error`, rejecting every pending waiter at once; when the socket closes before the child exits, it waits at most `HOST_EXIT_GRACE_MS = 700 ms` to fold the **exit code** into the error (total still ≤2 s), so "crashed" and "was closed" stay distinguishable.
- **The stdin guard is written in one place** (new `scripts/lib/host-spawn.mjs`): `hostChildEnv()` pins `PIFORGE_HOST_STDIN_CONTROL=0` **before** merging the caller's env, and `spawnNodeHost()` spawns the node host uniformly. Twelve scripts moved onto the factory and their hand-written `...process.env` and guards were deleted (the previous version hand-wrote them per script, which caused two incidents: a duplicate `env:` overwrote the first half, dropping the endpoint and token, and the host hit EADDRINUSE immediately).
- **`smoke:prefix-budget` is visible per step**: each step prints a start/end line (with duration), and a step exceeding `PIFORGE_SMOKE_STEP_TIMEOUT_MS` (300 s by default) kills the whole process tree and exits with 124; on Windows via `taskkill /F /T`, so measure-prefix being killed does not leave a host child behind.
- Fixing an environment dependency in the `codemode-worker-pool` test: `applyCodemodeWorkerPool` resolved from a module-load snapshot when no env was passed, which is guaranteed red inside a host child that carries `PI_CODEMODE_MAX_WORKERS=2`; it now passes `env: {}` explicitly.

## Did default behavior change

Yes, in five places:

1. **codemode defaults to `on`** (v0.9.4 defaulted to `only`): tools are declared back to the model one by one. Configurations that explicitly set `only` are unaffected.
2. **A shell call without an explicit `timeout` is interrupted at 45 s (300 s for heavy ones)**, tighter than last release's 120 s / 900 s. Long-lived processes and full packaging must pass `timeout` explicitly.
3. **The tool output budget goes 4000 → 24000 characters**: fewer truncations, but each result occupies more context (`read` tiers unchanged).
4. **Soft cap 4 / hard cap 8 tool calls per user turn**: from call 4 a self-check reminder is appended to the result, from call 8 a "deliver conclusions first" notice. These are text appended to the result; they do not block calls.
5. **The scheduler's heavy quota widens** to global 6 / per-session 4 (the light tier is unchanged).

## How to use the switches

- Output budget: `PIFORGE_TOOL_OUTPUT_CHARS` (500–200000, default 24000).
- Timeout guard: `PIFORGE_TOOL_GUARD=0` turns it off entirely; thresholds go through `PIFORGE_TOOL_TIMEOUT_SECONDS` / `PIFORGE_TOOL_TIMEOUT_HEAVY_SECONDS` / `PIFORGE_TOOL_TIMEOUT_MAX_SECONDS` / `PIFORGE_TOOL_MAX_PARALLEL`.
- Scheduler: `PIFORGE_TOOL_SCHEDULER=0` turns it off; quotas go through `PIFORGE_SCHED_GLOBAL_HEAVY` / `PIFORGE_SCHED_GLOBAL_LIGHT` / `PIFORGE_SCHED_SESSION_HEAVY` / `PIFORGE_SCHED_SESSION_LIGHT` / `PIFORGE_SCHED_MAX_WAIT_MS` / `PIFORGE_SCHED_QUEUE_HINT_MS` / `PIFORGE_SCHED_MAX_HOLD_MS`.
- codemode: the settings page "extensions and MCP → Codemode" switches `on` / `only`; the worker pool cap is set in the same place (1–8), priority settings page > `PI_CODEMODE_MAX_WORKERS` > 2.
- Debug logs: `PIFORGE_DEBUG_TOOL_GUARD=1`, `PIFORGE_DEBUG_TOOL_SCHEDULER=1`.
- Timeout for smoke / measurement scripts: `PIFORGE_SMOKE_STEP_TIMEOUT_MS` (default 300000).

## Known limitations

- The scheduler and the tool budget only take effect on the host side; running the pi CLI directly does not inherit these defaults.
- After a script timeout, a codemode worker slot is only released once the worker really exits; we can only **infer** that and log it, since there is no queue-state API (and we do not patch `node_modules`).
- The per-turn call budget is a prompt plus a reminder appended to results, not a hard block: the model can still exceed 8 calls, it is just told explicitly to wrap up.
