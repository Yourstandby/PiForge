# PiForge v0.9.4

发布日期：以 tag `v0.9.4` 的 CI 产出为准（Windows NSIS + ZIP，Linux deb，macOS universal）。

> **为什么有 0.9.4**：`v0.9.3` 的 tag 跑了 `desktop-packages.yml`，Windows / Linux 通过，
> macOS 在打包末尾的 `smoke-packaged-standalone` 里挂在
> `smoke-extension-ui-bridge.mjs` 的 `timed out waiting for a frame`。
> 0.9.3 没有产出 Release，本版 = 0.9.3 的全部内容 + 这条冒烟/流水线修复，
> 代码层面**与 0.9.3 没有功能差异**（旧 tag 不重写，按语义化版本往前推一位）。

## 本版主题一：修复发布流水线的假红

`smoke-extension-ui-bridge.mjs` 原来只报一句 `timed out waiting for a frame`，看不出卡在哪一步，
且单帧预算写死 20 s。macOS runner 冷启动（APFS + 首次读几万个 `node_modules` 文件）比本地慢
数倍，一次**正常但慢**的启动就会被判成 Host 死锁。

改动（`scripts/smoke-extension-ui-bridge.mjs`）：

- 单帧等待 20 s → 默认 60 s，可用 `PIFORGE_SMOKE_UI_TIMEOUT_MS` / `PIFORGE_SMOKE_TIMEOUT_MS`
  覆盖（与 `smoke-packaged-static.mjs` 既有约定一致）。
- `waitFor` 改为**队列匹配**：不匹配的帧不再被丢弃。旧实现「取一帧 → 对谓词 → 不对就丢」，
  在等 `agent.subscribe` 回复期间先到达的 `extension_ui_request` 事件会被永久吞掉，
  之后等它必然超时——这是脚本自身的真 bug，不只是预算问题。
- 超时信息带阶段标签与最近收到的帧类型：
  `timed out waiting for agent.create response after 60000ms; recent frames: res#1, evt:session_state`。
- 每阶段打点（`host ready` / `handshake ok` / `agent.create ok` / `agent.subscribe ok` /
  `extension_ui_request received` / `marker confirmed`），失败时附 Host 输出尾部 15 行。
- 超时类失败自动重试一次（`PIFORGE_SMOKE_UI_ATTEMPTS`，默认 2）。
- `scripts/smoke-packaged-standalone.mjs` 打印 `UI bridge smoke took <ms>`，CI 上一眼分辨
  「卡死」还是「慢但能过」。

`.github/workflows/desktop-packages.yml`：

- 顶层 `PIFORGE_SMOKE_UI_TIMEOUT_MS: "180000"`（CI 再给 3 倍余量）。
- macOS 打包冒烟失败时追加一步「用仓库编译的 Agent Host 再跑一遍同一冒烟」：
  过了 = 问题在打包产物（布局 / 符号链接 / 依赖解析），也过不了 = 环境时序问题。

## 本版主题二：调用压缩（与 0.9.3 同内容）

**同样的任务少问几轮**。不删工具、不降能力，只压缩「模型往返次数」和「thinking 占 output」：

- codemode 默认开启且默认 `only`（普通工具不再声明给模型，改由一次脚本批量调用；
  设置页「扩展与 MCP → Codemode」可切回「照常声明工具」）。
- 提示词新增四条批量/预算静态常量（批量优先、先引用后补测、调用预算、报错先读完 traceback）。
- 截断续读引导改成「一次 codemode 脚本批量读 / `tool_history_get` 翻页」。
- Host 首次启动补写 `defaultThinkingLevel: "low"`（仅在该键缺失时，原子写，设置页可改回）。

以及 0.9.3 已包含的夜晚模式、思考边流边看、消息时间、压缩前提问可见、打包版图片缩放等，
见 [`v0.9.3.md`](./v0.9.3.md) 与 [`CHANGELOG.md`](../../CHANGELOG.md)。

## 验证

| --- | --- | --- |
| 类型检查 | `NODE_OPTIONS=--max-old-space-size=6144 npx tsc --noEmit` | exit 0（默认 heap 会 OOM，需抬高） |
| Lint | `npm run lint` | 0 error（5 条既有 warning） |

| 冒烟超时路径 | `PIFORGE_SMOKE_UI_TIMEOUT_MS=2000 node scripts/smoke-extension-ui-bridge.mjs` | 按预期报 `host did not report ready within 2000ms` 并附 Host 尾部输出 |

未在本版覆盖：真实 macOS runner 上的时序（本地无法复现），打包产物的三平台冒烟以 CI 为准。

## 产物

安装包 / deb / dmg 由 `desktop-packages.yml` 在 push `v0.9.4` tag 后于 CI 构建（NSIS + ZIP +
`latest.yml` + deb + macOS universal dmg/zip + `SHA256SUMS.txt`），本地不重复构建。

## 迁移与升级

- 从 0.9.3 升级无需迁移动作（0.9.3 未产出 Release，直接从 0.9.2 升级亦可）：会话与设置分别在
  `~/.pi` 与 `%APPDATA%\piforge`。
- 首次启动会写一行 `defaultThinkingLevel: "low"`（仅缺失时写一次）。
- 新会话默认走 codemode；不想要批量层可在设置里关闭，工具恢复直呼。
