# PiForge v0.12.2 — conversations stop disappearing, queued messages are editable, plans get an ending

**English** · [简体中文](./v0.12.2.zh-CN.md)

Released: 2026-11-24

The previous public version was v0.12.1. There are no new switches in this release: two small features that fill in missing entry points, and everything else is a fix for things that "looked broken" — a blank conversation while tools run, queued messages that could only be deleted, plans that vanished halfway, and a prefix cache that broke as soon as MCP connected.

## Highlights

### The conversation is no longer blanked out while running

While a session runs tools (`running: codemode` / `running: bash`) the conversation area went blank, leaving only "PiForge is thinking…", which looked like the whole app had hung — even though the session file actually held dozens of complete records.

The root cause was two silent clearing paths: calling `setMessages([])` whenever `fetchSession` returned null (host busy / write race), and overwriting when a re-fetch of the same session produced an empty `context.messages`. A running round re-fetches the same session repeatedly, so hitting either one meant permanent blankness — only `agent_end` reloads before the round ends, and `agent_end` is exactly the event that has not happened yet.

Both cases now keep what is already on screen; when the agent is running and there really are 0 history entries, the UI explains the situation, offers a "reload" button, and retries automatically 6 times with 1.5s → 6s backoff, stopping as soon as history returns.

### Queued messages can be edited, sent immediately, and moved to the front

Queued follow-ups could previously only be deleted: to change one sentence you had to delete and retype it (losing attachments and order), to jump the queue you had to click "move up" repeatedly, and to send right away you had to wait for the round to finish.

- **Click the text or the pencil to edit in place** (Enter saves / Esc cancels), keeping the id, position and attachments; delete is hidden while editing.
- **⚡ Send now**: steers during streaming, starts a new round when idle; a failed steer degrades to a new prompt, and if that is rejected the message goes back into the queue unchanged.
- **⏫ Move to the front**: the host queue gains `update` / `take` / `restoreAt`; `take` returns the original index, and a failed delivery puts the message back where it was.

### Plans no longer rot

A plan vanishing the moment it stopped at 3/6 was the inevitable outcome of the old implementation: as soon as "the round ended and it was not waiting for approval", progress simply returned null — the user did not know what remained, and the model never brought it up again.

An unsettled plan on a stopped agent now keeps a "not finished" card with two exits: **continue with the rest** / **drop the rest**. `dropped` becomes a terminal state (not counted as done, and no extra settlement round). Two visual fixes come with it: completed steps lose the strikethrough (`done` and `dropped` used to share `line-through`, so "finished" looked like "deleted"), and when the list is expanded finished steps collapse into one "N steps done" line; sending a new round invalidates the previous round's `livePlan`, so the card no longer lingers above the input for 1-2 seconds.

### A connected MCP server no longer breaks the prefix cache

The MCP extension re-renders `sections.mcp_servers` from live state every round. Indirect servers (codemode / deferred) do not wait for a connection in the first round, and `connection.instructions` is only added to the description once connected — a change to those bytes makes the whole history a miss and resends it.

The first bytes are now latched under a signature of "server name + exposure mode": as long as the signature holds, the old bytes are reused, and only a real configuration change (adding / removing / toggling a server) swaps them once. The MCP load and discovery paths are unchanged.

### Other fixes

- **Delivery state is visible**: after a steer / queued submit the bubble shows "delivering…" until the host takes it.
- **One submit per 800ms of the same text**: double-clicking send or mashing Enter no longer produces two duplicate bubbles in the same second.
- **No "0 produced this round" before the first token**: it now reads "waiting for the first token…" and states that the message reached the host.
- **tokens/s does not freeze**: it drops to zero when thinking / streaming ends; the rate on a tool card only shows while running.
- **No more flashing "reconnecting event stream"**: the reconnect counter resets when the round ends, and `evaluateStreamHealth` gains a 3s grace at the start.
- **Images have exactly one sizing rule**: message images `max-h-64`, tool-produced images `max-h-72`, both now bounded in width and height, so wide images are no longer clipped sideways.
- **Clickability rules unified**: a bare file name is always plain text, and only a separator or an `@` prefix makes a link; external links allow only http / https / mailto / tel.
- **The fleet / orchestrator panels gain a manual spawn entry**: the `AgentSpawnTrigger` form (name may be left empty to auto-name, plus a task brief) and the new RPC `herdr.spawn`, so you need not wait for the main agent to call a tool.

## Behavior changes (please note)

- A plan card in "not finished + agent stopped" now stays until you press "continue" or "drop the rest".
- `tokens/s` only shows while running and drops to zero when finished; completed plan steps no longer carry a strikethrough.
- The maximum height of assistant-body / markdown inline images drops from 320 to 256 (the same rule as user bubbles); tool-produced images stay at 288.
- Plan is still read-only, and the approval flow and card position are unchanged; the MCP load, discovery and config read/write paths are unchanged.

## Install notes

The three installers are still unsigned, as in v0.12.1:

- **Windows**: SmartScreen will block it; choose "More info → Run anyway".
- **macOS**: Gatekeeper will block it; right-click → Open, or run `xattr -dr com.apple.quarantine`.
- **Linux**: the `.deb` is unsigned and needs `sudo dpkg -i` (the AppImage runs directly).
