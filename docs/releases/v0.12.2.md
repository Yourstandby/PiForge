# PiForge v0.12.2 — 对话不丢、排队能改、计划有收尾

发布日期：2026-11-24

上一个公开版本是 v0.12.1。本次没有新开关，两个补入口的小功能，其余全是「看着像坏了」的修复：
跑工具时对话区空白、排队消息只能删、计划停在半路就消失、MCP 一连上就打破前缀缓存。

## 亮点

### 运行中不再把对话区抹成空白

会话在跑工具（`running: codemode` / `running: bash`）时对话区一片空白，只剩一句
「PiForge 正在思考…」，看起来像整个应用卡死 —— 而会话文件里其实有完整的几十条记录。

根因是两条静默清空路径：`fetchSession` 返回 null（宿主忙 / 写盘竞态）时直接 `setMessages([])`；
同一会话重取到空 `context.messages` 时覆盖。运行中的回合会反复重取同一会话，一旦撞上就永久空白 ——
本轮结束前只有 `agent_end` 会触发重载，而 `agent_end` 恰恰是还没发生的那件事。

现在这两种情况都保留已上屏对话；运行中且确实 0 条历史时给出说明 + 「重新加载」按钮，
并按 1.5s → 6s 退避自动补取 6 次，历史回来即停。

### 排队消息能改、能抢发、能插队

排队的后续消息以前只能删：想改一句话得删了重打（附件和顺序一起丢），想插队只能连点上移，
想马上发只能等这一轮跑完。

- **点击文案或铅笔就地编辑**（Enter 保存 / Esc 取消），保留 id、位置与附件；编辑态隐藏删除按钮。
- **⚡ 立即发送**：流式中走 steer，空闲直接开新一轮；steer 失败退成新 prompt，prompt 被拒则原样回队。
- **⏫ 插到队首**：宿主队列新增 `update` / `take` / `restoreAt`，`take` 带回原下标，
  投递失败按原位置放回。

### 计划不会烂尾

计划停在 3/6 就凭空消失是旧实现的必然结果：只要「本轮结束且不在等批准」，进度就直接返回 null，
用户不知道还剩什么，模型也不会再提。

现在未结算且已停机的计划会留着一张「未完成」卡，给两个出口：**继续执行剩余** / **放弃剩余**。
`dropped` 成为终态（不算完成，也不额外跑一轮结算）。顺带两处观感修正：完成态不再划删除线
（以前 `done` 和 `dropped` 共用 `line-through`，「做完了」看起来像「被删掉」），
已完成步在展开列表时收成「已完成 N 步」一行；新一轮发出即作废上一轮的 `livePlan`，
卡片不再在输入框上方残留 1-2 秒。

### MCP 连上后不再打破前缀缓存

MCP 扩展每轮按 live 状态重渲染 `sections.mcp_servers`。间接服务器（codemode / deferred）首轮不等
连接，连上后 `connection.instructions` 才补进描述 —— 这段字节一变，整段历史就按未命中重发。

现在按「服务器名 + 暴露方式」签名锁存首次字节：签名不变就沿用旧字节，真改配置（增删 / 开关服务器）
才换一次。MCP 的加载与发现路径没有改。

### 其余修复

- **投递态可见**：steer / 排队提交后气泡下方显示「投递中…」，被宿主接住即消失。
- **同一段话 800ms 内只提交一次**：双击发送、Enter 连按不再产生两条同一秒的重复气泡。
- **首 token 之前不报「本轮产出 0」**：改成「等待首个 token…」，并说明消息已送达宿主。
- **tokens/s 不冻结**：思考 / 流式结束后归零；工具卡上的速率只在运行中显示。
- **不再闪「事件流重连中」**：本轮结束即清零重连计数，`evaluateStreamHealth` 增加 3s 起步宽限。
- **图片只有一个尺寸口径**：消息图 `max-h-64`、工具产出图 `max-h-72`，都补宽高双限，
  宽图不再被横向裁掉半张。
- **可点击性判定统一**：裸文件名一律纯文本，只有带分隔符或 `@` 前缀才成链接；外链只放行
  http / https / mailto / tel。
- **舰队 / 编排面板补手动派生入口**：`AgentSpawnTrigger` 表单（名称可留空自动取名 + 任务简报），
  新增 RPC `herdr.spawn`，不必等主 Agent 调工具。

## 行为变化（请注意）

- 计划卡片在「未完成 + 已停机」时会一直留着，直到点「继续执行」或「放弃剩余」。
- `tokens/s` 只在运行中显示，跑完归零；计划完成态不再有删除线。
- 助手正文 / markdown 内联图片的最大高度从 320 降到 256（与用户气泡同一口径），
  工具产出图仍是 288。
- plan 仍只能读不能写，批准流程与卡片位置不变；MCP 的加载、发现与配置读写路径不变。

## 安装提示

三端安装包仍未签名，与 v0.12.1 相同：

- **Windows**：SmartScreen 会拦，选「更多信息 → 仍要运行」。
- **macOS**：Gatekeeper 会拦，右键 → 打开，或执行 `xattr -dr com.apple.quarantine`。
- **Linux**：`.deb` 未签名，需 `sudo dpkg -i`（AppImage 直接运行）。
